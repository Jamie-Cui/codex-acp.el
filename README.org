* codex-acp.el

Use local Codex from an Emacs ACP (Agent Client Protocol) frontend, with Emacs
workspace tools for local and TRAMP projects. This supports running Codex locally
while working on code on an SSH host.

The package provides a client factory. The frontend handles the chat interface,
input, and permission prompts. Codex communicates with the adapter over stdio;
local ~tramp-async~ workers handle file operations, commands, and remote skill
reads, using TRAMP to reach the target host.

#+begin_example
ACP frontend --> codex-acp.el --> local codex app-server
                       |
                       +--> tramp-async worker --> local / TRAMP project
#+end_example

The remote host does not need Codex installed. No additional TCP listener or
project file mirror is required.

** Features

- Text and inline raster image prompts, streamed responses, and turn cancellation.
- Session listing, resuming, forking, and asynchronous title generation.
- Model and reasoning effort selection, using the models returned by app-server.
- Local and remote skill discovery through the frontend's available commands.
- File reads, directory queries, file writes and replacements, and command
  execution with literal argv arguments.
- Additional input during an active turn (steering) and account quota queries,
  when the frontend integrates the corresponding extension APIs.

** Requirements and setup

Requirements:

- Emacs 30.1 or newer.
- External Elisp packages: ~acp~ 0.17.1 or newer and ~async~ 1.9.9 or newer.
  ~async~ starts the local Emacs workers.
- Codex CLI 0.162.1 or newer, installed and authenticated locally.
- An ACP frontend that supports a custom client factory and permission requests.

This repository includes ~tramp-async.el~ (currently version 0.4.0),
~codex-acp-worker.el~, and ~acp-image.el~. No separate installation of
~tramp-async~ is needed. The remaining direct dependencies, including TRAMP,
JSON, and Dired, are provided by Emacs.

Check the CLI version and sign in from a local terminal:

#+begin_src sh
codex --version
codex login
#+end_src

After installing ~acp~ and ~async~, add the complete repository directory to
~load-path~, keeping all four ~.el~ files together. Replace the path below with
your checkout location:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/codex-acp.el")
(require 'codex-acp)
#+end_src

Loading the library does not start Codex. Creating a client checks the CLI
version and starts a local app-server process. If GUI Emacs cannot find the CLI,
set ~codex-acp-program~ to its absolute path.

SSH workspaces require a local SSH client and noninteractive authentication to
the remote host. Workers run as local child Emacs processes. They inherit the
process environment, but do not load the interactive Emacs init file or inherit
its credential caches. Use ~tramp-async-worker-settings~ to pass explicit TRAMP
settings when needed; do not store credentials there.

** Frontend integration

Set the frontend's client factory to ~#'codex-acp-make-client~. The registration
mechanism depends on the frontend. This package does not provide a standalone
interactive chat command.

The factory accepts an optional conversation buffer and scope:

#+begin_example
(codex-acp-make-client &optional buffer scope)
#+end_example

- ~buffer~ defaults to the current buffer. Its ~default-directory~ determines
  the session workspace: for example, ~/absolute/path/to/project/~ for a local
  project or ~/ssh:user@host:/path/to/project/~ for a remote project. Keep the
  complete TRAMP prefix.
- ~scope~ defaults to ~directory~, restricting file access to the project and
  approved directories. Pass ~host~ explicitly for a general conversation on
  the same host. Writes and commands still require approval.
- The frontend should retain the client, handle updates and permission requests,
  and call ~acp-shutdown~ when finished. Use asynchronous ACP APIs such as
  ~acp-send-request~. Each client supports one session.

The ~cwd~ supplied when creating a session must match the conversation buffer's
initial working directory. Relative paths and commands without an explicit
~cwd~ continue to use that initial directory; attachments do not change it.

Frontends can use ~codex-acp-steer-ready-p~ and ~codex-acp-steer~ to add input to
an active turn, ~codex-acp-read-rate-limits~ to query account quota, and
~codex-acp-rename-session~ to rename a session.

** Permissions and file behavior

By default, reads are allowed within the project and advertised skill
directories. Access to another directory prompts for a grant lasting either
the current turn or the current connection. Reconnecting requires a new grant.
Mentioning a path or attaching a file does not grant directory access.

Writes and commands require ACP permission approval. A directory grant expands
the accessible paths but does not approve writes or commands. Operations that
need approval fail if the frontend has no permission handler.

Commands receive literal argv arguments. Pipes, redirection, and other shell
syntax are not interpreted automatically; invoke a shell explicitly when
needed. Commands run with the target host user's permissions. The project
directory is a working directory, not an OS sandbox. Approved SSH commands and
scp/rsync transfers use the same permission flow. Tunnels, port forwarding, and
public network exposure are prohibited. File tools and command working
directories remain on the session host.

Writes are rejected when the target has a modified visiting buffer. Clean
visiting buffers are guarded against edits while a write is in progress.
Tools do not revert buffers automatically; inspect and refresh them as needed.
If a worker reports uncertain side effects, inspect the target before retrying.

** Skills and session history

Local skills come from Codex's list of enabled skills. TRAMP sessions also
search the following remote project and user directories. Each skill occupies
a direct child directory of a skill root:

#+begin_example
<project>/.agents/skills/<name>/SKILL.md
<project>/.codex/skills/<name>/SKILL.md
<remote-home>/.agents/skills/<name>/SKILL.md
<remote-home>/.codex/skills/<name>/SKILL.md
#+end_example

Available commands appear as ~$name~. Name collisions receive a source prefix
or numeric suffix; use the names shown by the frontend. Workers read selected
remote skill content and add it to the prompt.

Sessions are stored by local Codex and separated by project-specific control
directories. For local projects, the history list also includes native Codex
sessions for that project. Their metadata asks the frontend to open them with
the external backend.

After an unnamed session completes its first successful turn, the adapter makes
one additional model request without tools to generate a title. Resuming an
unnamed session also triggers a naming attempt. Naming runs asynchronously;
a failure does not fail the conversation.

** Configuration

Use ~M-x customize-group RET codex-acp RET~ to configure the adapter.

- ~codex-acp-program~: local CLI executable; defaults to ~"codex"~.
- ~codex-acp-model~: initial model; defaults to ~nil~, using the local Codex
  default. The frontend can also expose model and effort choices once the
  session is established.
- ~codex-acp-server-arguments~: additional app-server argv arguments; defaults to
  ~nil~. The adapter appends its workspace isolation settings after these
  arguments.
- ~codex-acp-command-timeout~: approved command execution timeout; 120 seconds.
- ~codex-acp-request-timeout~: control request timeout; 30 seconds. This is not
  a timeout for model turns.
- ~codex-acp-title-timeout~: asynchronous title generation timeout; 120 seconds.
- ~codex-acp-file-size-limit~: maximum file size for reads and writes; 4 MiB.
- ~codex-acp-output-limit~: maximum characters retained from a file or command
  result; 65,536.
- ~codex-acp-json-size-limit~: maximum size of a single JSON message; 64 MiB.
  Inline image payloads have a separate limit.

Image size is controlled by ~acp-image-max-bytes~ in the ~acp-image~ customization
group, with a default limit of 20 MiB of decoded data per image. PNG, JPEG,
WebP, and GIF are supported. MIME type, actual image type, and Base64 encoding
are validated before transmission. Images are sent as inline data URLs;
history restoration does not download external images or read image file paths.

** Limitations and troubleshooting

The adapter uses Codex's experimental dynamic-tool API. Compatibility should be
checked after CLI upgrades. Audio and external MCP servers are not supported.
Native shell execution, hooks, plugins, child agents, browser access, and web
search are disabled. Workspace operations go through Emacs tools. Synchronous
ACP requests are not supported.

- Library loading fails: check that ~acp~ and ~async~ are available and that the
  complete repository directory is on ~load-path~. The repository supplies
  ~tramp-async.el~ and ~acp-image.el~. If other versions are installed, use
  ~M-x locate-library~ to check which copy Emacs finds.
- Interactive TRAMP works but a worker cannot connect: check whether SSH relies
  on interactive password entry, Emacs credential caches, or variables set only
  in your init file. Workers have a separate startup environment.
- The CLI cannot start: check that Emacs can find ~codex-acp-program~, that its
  version meets the requirement, and that you have signed in locally.
- Session directory mismatch: compare the conversation buffer's
  ~default-directory~ with the request's ~cwd~. Preserve the full TRAMP prefix
  for remote projects.
- A write is rejected: check the permission decision and whether the target has
  a modified visiting buffer. Do not overwrite or revert unsaved edits.

** Development

- [[file:codex-acp.el][codex-acp.el]]: protocol translation, client and session lifecycle,
  permissions, and streaming.
- [[file:codex-acp-worker.el][codex-acp-worker.el]]: worker-side path validation, file and
  command operations, and remote skill reads.
- [[file:tramp-async.el][tramp-async.el]]: bundled asynchronous I/O implementation, including
  local workers, file and command queues, cancellation, timeouts, and visiting
  buffer write protection. The adapter uses its API directly; enabling
  ~tramp-async-files-mode~ for interactive file operations is not required.
- [[file:acp-image.el][acp-image.el]]: inline image validation and conversion.

The repository currently has no automated test suite or build script. After
editing Elisp, run these basic syntax and diff checks from the repository root:

#+begin_src sh
emacs -Q --batch --eval '(dolist (file (quote ("acp-image.el" "tramp-async.el" "codex-acp-worker.el" "codex-acp.el"))) (with-temp-buffer (insert-file-contents file) (emacs-lisp-mode) (check-parens)))'
git diff --check
#+end_src

These checks do not load project dependencies or verify session behavior.
When dependencies are available, byte-compile the changed libraries and verify
permissions, cancellation, timeouts, and behavior after shutdown in the affected
local or TRAMP workflows.
